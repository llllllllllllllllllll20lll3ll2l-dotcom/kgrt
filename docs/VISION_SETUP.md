# 👁 Распознавание карт и координаты кликов

Документ объясняет, **как бот видит вашу руку и куда нажимает**. Это самая
хрупкая часть: игра не даёт API, поэтому всё держится на геометрии экрана.

## Как бот узнаёт карту в руке

1. Кадр с телефона делится на 4 области — по одной на каждую карту в руке.
2. Каждая область сравнивается с иконками карт из `data/templates/`
   (метод `cv2.matchTemplate`, сравнение по нормализованной корреляции).
3. Иконка-шаблон на экране примерно в **2.4 раза крупнее**, поэтому масштаб
   перебирается от 1.9 до 2.85.
4. Побеждает карта с максимальным совпадением. Если совпадение слабое
   (меньше 0.28) или отрыв от второго места маленький (меньше 0.05),
   слот считается нераспознанным — бот лучше пропустит ход, чем поставит не то.

Проверено на реальном кадре 720x1604 (ваш скриншот): **4 из 4 слотов** верно,
отрыв от второго места 0.10–0.40.

## Почему раньше писало «Не выбрана карта»

Старый код считал координаты карт по формуле `x = 0.15 + slot*0.22`, то есть
для первого слота ~108 px по ширине. Настоящая первая карта стоит на ~223 px.
Клик уходил в зону «След.» слева — карта не выбиралась, и при повторном клике
по арене игра отвечала «Не выбрана карта».

Теперь координаты такие (для экрана 720x1604):

| Слот | Центр по X | Клик (x, y) |
|------|-----------|-------------|
| 0 (левая)  | 0.311 | (223, 1424) |
| 1          | 0.500 | (360, 1424) |
| 2          | 0.682 | (491, 1424) |
| 3 (правая) | 0.874 | (629, 1424) |

Ваши точки (460/510/558/617 по X в окне бота) дали 0.303 / 0.491 / 0.670 / 0.891 —
то есть те же места, разница в пределах пары пикселей.

## Куда бот ставит карты

Игра разрешает ставить карты только на **своей половине** (ниже мостов).
Все точки зажаты в зону `y` от 0.455 до 0.80, поэтому клик никогда не уйдёт
на чужую территорию (иначе игра откажет в установке).

| Точка | Координаты (доли) | Для чего |
|-------|-------------------|----------|
| `left_bridge` / `right_bridge` | 0.22 / 0.79, y 0.47 | начало атаки |
| `left_mid` / `right_mid` | 0.22 / 0.79, y 0.525 | поддержка, танк за мостом |
| `left_def` / `right_def` | 0.28 / 0.72, y 0.56 | защита перед башнями |
| `left_back` / `right_back` | 0.13 / 0.87, y 0.66 | безопасно, сзади |
| `center` | 0.50, y 0.505 | центр, цикл |
| `king` | 0.50, y 0.665 | перед королём |

Мост слева на кадре — x ≈ 0.218, справа — x ≈ 0.788. Башни-принцессы:
x 0.22 и 0.79, y ≈ 0.59. Король: x 0.50, y ≈ 0.67.

## Если на вашем телефоне клики промахиваются

```bat
python tools/calibrate.py
```

Скрипт:
- напечатает, какие карты распознаны и с какой уверенностью;
- сохранит `calibration_marked.png` — зелёные рамки = распознано,
  красные = не распознано;

```bat
python tools/calibrate.py --tap
```
- дополнительно сделает пробный клик по первому слоту (карта должна подсветиться).

Проверка без телефона (синтетический кадр из шаблонов):

```bat
python tools/selftest.py
```

## Как добавить новые карты

1. Сделайте скриншот руки в бою, вырежьте иконку карты (вместе с рамкой).
2. Сохраните как `data/templates/<card_id>.png`, где `card_id` — id из
   `data/cards.json` (например `princess.png`, `witch_evo.png`).
3. Запустите `python tools/selftest.py`.

Чем ближе иконка к тому, как карта выглядит в руке, тем выше точность.
Учтите: у эволюций отдельная иконка, поэтому `witch.png` и `witch_evo.png`
нужны оба.

## Ограничения

- **Разрешение.** Все координаты относительные, поэтому 1080x2400 тоже должно
  работать. Но если у телефона нестандартные пропорции, точку Y надо проверить
  через `calibrate.py`.
- **Сдвиг руки.** Игра чуть покачивает карты и подсвечивает доступные, поэтому
  область поиска взята с запасом (±0.115 ширины вокруг центра слота).
- **Похожие карты.** Скелеты и Скелеты (Эволюция) на мелком кадре похожи;
  если бот путает — проверьте уверенность в логе и `calibration_marked.png`.
- **Эликсир.** Бот не ставит карту, если эликсира не хватает: это проверяется
  и по распознанному значению, и по стоимости карты.

## Скорость (задержка)

Раньше между кадром и решением проходило больше 3 секунд, и бот опаздывал.
Сейчас узкие места устранены:

| Что было | Что стало |
|---|---|
| запуск `adb.exe` на каждый кадр (~100 мс) | непрерывный поток кадров, один процесс на бой |
| PNG-кодирование кадра (~54 мс) | сырые пиксели (RGBA) напрямую |
| распознавание руки 1290 мс | **55 мс** (двухэтапный поиск) |
| `time.sleep(1.5)` в цикле | 5 мс |
| запуск `adb.exe` на каждый клик | постоянный `adb shell` |
| превью тормозило решения | превью в отдельном потоке |

Итог на кадре 720x1604: **анализ ~55 мс**, захват в потоковом режиме
практически бесплатный. Решения принимаются 10 раз в секунду,
после постановки карты бот выжидает 0.8 с (рука меняется, эликсир тратится).

Замерить на своём телефоне:

```bat
python tools/benchmark.py
```

Скрипт покажет время захвата каждым способом, время анализа и ожидаемое
число кадров в секунду. В статусе бота эти же цифры видны в реальном времени:
`Эликсир 6.0 • Время 142с • Рука: ... • 12 кадр/с (захват 8 мс, поток)`.

### Если поток кадров не заводится

Некоторые прошивки не поддерживают `screencap` в цикле. Тогда бот сам
переключается на одиночные raw-кадры, а при проблемах — на PNG. В статусе
будет указано, какой режим используется: `поток`, `raw` или `png`.
